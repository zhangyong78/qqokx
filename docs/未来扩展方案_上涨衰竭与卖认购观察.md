# 未来扩展思路：日线大涨后的上涨衰竭与卖认购观察

> 状态：未来扩展构想，尚未实现。本文用于记录方向，不代表当前程序已经具备相关采集、提醒或交易能力。
>
> 记录日期：2026-10-19

## 1. 背景与目标

日线出现一段明显上涨后，不把“涨幅大”直接解释为卖认购时机，而是先进入上涨衰竭观察期。观察阶段主要回答：

- 上涨期间是否仍有新增持仓与持续买盘支持？
- 上涨是否主要由空头回补或强平推动？
- 强平峰值过去后，价格是否开始滞涨，均线斜率是否减弱，短周期结构是否转弱？
- 期权隐含波动率和权利金是否足以补偿承担的风险？

系统定位为**行情观察与决策辅助**。第一阶段不自动下单，也不把分数直接转换成卖 Call 指令。

## 2. 当前项目基础与缺口

- 项目已有 K 线 SQLite 缓存，可复用为价格与结构分析的数据基础。
- 项目已有 Deribit 波动率查看与监控相关模块，可在后续评估是否复用。
- 当前代码检查未发现 OI、强平事件和 OKX 期权 IV 的专用持续采集及历史存储链路。
- 因此，后续分析不能假设这些数据已具备可回溯历史；OI 与强平需要从采集开始后逐步积累。可由交易所回补的历史数据也应按接口实际范围处理。

## 3. 观察流程

### 阶段 A：日线大涨，建立观察事件

用已收盘日线判断是否进入观察期。候选条件可以包括：一段窗口内涨幅显著、价格处于 EMA21/EMA55 上方、两条均线向上、突破近期结构高点。具体窗口和阈值以后用历史案例校准，不在本方案中固化。

每个观察事件保存起始时间、触发条件和规则版本。后续指标以该时间点为锚，避免把上涨之前的数据混入本轮判断。

### 阶段 B：观察上涨动力

- **价格上涨 + OI 上升**：视作新增持仓增加的线索，趋势延续风险仍在，不因涨幅大而急于卖认购。
- **价格快速上涨 + OI 下降 + OKX 观测到空头强平集中**：标记为“可能存在空头回补推动”，开始关注后续强平是否退潮。
- **资金费率**：作为多头拥挤程度的辅助背景，不单独作为反转信号。

OI 应优先保存美元或币本位口径，并同时保留交易所原始合约数及产品信息，避免不同合约单位直接混比。

### 阶段 C：等待衰竭与结构确认

观察价格是否反复冲高失败、创新高幅度缩小、长上影增多、上涨速度放缓；同时观察 EMA21 斜率是否减弱、强平峰值是否过去，以及短周期结构低点是否被破坏。

单一条件不应触发候选状态。更强的确认来自多项共振，例如：强平峰值已过、OI 不再显著下降、价格滞涨、EMA21 走平或转弱，并且短周期结构出现破坏。

### 阶段 D：形成卖认购候选

只有在上涨已经发生、动能有衰减迹象、价格出现滞涨或结构转弱、IV/权利金具备吸引力时，才显示卖认购候选。候选信息应区分：

- 有现货或 ETF 底仓：可以评估覆盖式卖 Call。
- 没有底仓、只是判断上涨空间有限：优先评估风险有限的熊市认购价差，不默认裸卖 Call。

候选不是自动交易信号；继续上涨、结构未破坏或数据缺失时，应明确显示“继续观察”。

## 4. 拟采集数据与用途

| 数据 | 初步来源与方式 | 用途与注意事项 |
| --- | --- | --- |
| BTC 现货/指数/永续价格、日线与短周期 K 线 | 复用项目 K 线链路；必要时补充用于结构确认的周期 | EMA21/55、涨幅、前高、上影、滞涨、结构低点。统一价格来源并在报告标明。 |
| 永续 OI | OKX `GET /api/v5/public/open-interest` 获取快照；优先评估 WebSocket `open-interest` 持续采样 | OI 端点快照不能替代本地时间序列；要按产品保存并统一单位。 |
| 资金费率 | OKX 当前费率与 `GET /api/v5/public/funding-rate-history` | 判断多头拥挤背景。历史接口有范围限制，不能将其当成无限期历史库。 |
| 强平事件 | OKX 公共 WebSocket `liquidation-orders` | 保存原始事件并按分钟汇总方向和规模。该频道不代表 OKX 全部强平量，更不代表全市场总量，只能描述为“OKX 观测到的强平”。 |
| 期权 IV 曲面快照 | OKX `GET /api/v5/public/opt-summary` | 保存 ATM `volLv`、各合约 `markVol/bidVol/askVol`、期限、Delta 等；按统一期限或 Delta 选样，避免不同行权价直接比较。 |
| 期权成交 IV | OKX `GET /api/v5/public/option-trades` 或 WebSocket `option-trades` 的 `fillVol` | 作为成交 IV 补充。接口返回近期有限记录，若要有历史序列仍需持续保存；注意成交量和样本稀疏度。 |
| 成交量与量价特征 | 现有 K 线/成交数据 | 辅助辨别上涨是否放量、动能是否衰减，不单独决定方向。 |

OKX 官方文档：

- [OKX API V5 文档（公共数据：OI、资金费率、期权市场数据）](https://app.okx.com/docs-v5/en/)
- [OKX API V5 文档（市场数据：期权成交及 `fillVol`）](https://app.okx.com/docs-v5/en/)
- [OKX API 变更日志（历史市场数据相关更新）](https://www.okx.com/docs-v5/log_en/)

实现时应再次核对 API 字段、限频、产品参数与历史回补能力，以届时官方文档为准。

## 5. 本地留存与恢复思路

优先沿用项目已有数据目录和 SQLite 习惯，建立专用行情表，不把这些记录混入账户或实盘仓位数据。最少保留：

- 交易所事件时间、程序接收时间、产品/合约标识、数据源；
- 原始数值、统一后的单位、计算使用的价格类型；
- 观察事件 ID、采集状态、最近成功时间和缺口信息；
- 原始强平事件的去重键，以及按分钟聚合后的方向和规模。

程序启动时恢复最近观察事件并继续采集；断线后记录缺口。能通过官方接口回补的数据按分页回补，无法回补的强平事件明确标成缺失，不用插值补造。对异常值、接口失败和时间戳倒退保留诊断信息。

如果采集依赖桌面程序运行，程序关闭期间会产生数据空档。未来实现时需明确提示采集覆盖情况；是否增加后台常驻或 Windows 计划任务，应根据实际使用方式另行决定。

## 6. 评分与提醒设计

可以提供“上涨衰竭 / 卖认购评分”作为阅读摘要，分项展示而不是只给一个黑盒总分：

1. **趋势背景**：EMA21/55 方向、与 EMA55 的距离、近期结构高点突破情况。
2. **上涨来源**：价格与 OI 的组合、资金费率状态、OKX 观测到的多空强平量及其相对近期基线的异常程度。
3. **动能衰减**：冲高失败、涨幅变小、上影变化、EMA21 斜率、成交量变化。
4. **结构转弱**：是否跌破本轮上涨中的有效短周期低点；明确结构周期和确认方式。
5. **卖方定价**：ATM IV 的历史分位、期限结构、Call 端偏斜，以及目标 Delta/到期日的可得权利金。

评分用于排序与解释，不能抵消结构未转弱、趋势仍强或数据质量不足等关键条件。提醒在状态变化时触发，例如“进入观察期”“衰竭信号增加”“进入卖认购候选”“数据采集中断”；无变化时不重复刷屏。

## 7. 分阶段实施建议

### 第一阶段：先积累数据并可查看

- 先以 BTC 为对象，采集并本地保存 OI、强平、资金费率、期权 IV 和必要价格序列。
- 展示最近值、变化趋势、数据缺口与数据源限制。
- 只生成观察报告，不发出自动交易动作；阈值保持可配置或仅做说明性标记。

### 第二阶段：用积累样本校准

- 用真实保存数据复盘上涨案例，比较“新多推动”和“空头回补推动”两类路径。
- 校准上涨触发、强平峰值、滞涨、结构破坏、IV 分位的阈值。
- 评估提醒是否过早、过频或漏掉观察阶段，再决定是否加入评分总览。

### 第三阶段：扩展标的与策略比较

- 再评估 588000 或其他标的的数据可得性、期权流动性和合约差异。
- 对覆盖式 Call 与熊市认购价差分别做历史案例分析，并把最大风险、权利金、到期和滚动条件纳入解释。
- 本阶段仍是分析辅助；任何实盘执行能力都需要独立设计、风险校验和验收，不由本方案默认为授权。

## 8. 主要限制与风险

- OKX 强平频道覆盖不完整，不能用作全市场精确强平总量。
- OI、IV 和期权成交数据的频率与历史回补范围不同；报告必须显示数据时间、来源和缺口。
- 不同产品 OI 单位、期限与期权 Delta 不同，必须归一化后才能比较。
- 期权 IV 可能缺报价或曲面拟合失败；缺失时不能拿旧值伪装成实时值。
- 大涨后趋势可能继续远超预期。因此“进入观察期”可以较早，“卖认购候选”应等待多项衰竭与风险收益条件确认。
- 评分是条件汇总，不代表胜率、收益保证或自动下单许可。

## 9. 未来开始实现时的首个交付目标

首个可验收版本应包括：持续采集与本地留存、断线/缺口显示、BTC 观察事件记录、关键指标趋势展示、状态变化提醒，以及一份可回看的解释报告。先确认数据连续性和展示口径，再讨论评分阈值；不把“数据能拿到”误认为“历史数据已经具备”。

# K 线自动通道模块设计

## 目标

把自动通道从独立窗口撤出，作为 K 线页面内的研究模块交付第一期能力：自动箱体与通道识别。模块只用于图表分析和告警展示，不增加任何自动下单行为。

## 用户界面

K 线左侧控制区新增“自动通道”分组，默认关闭。分组包含：

- `显示自动箱体`：显示当前有效箱体；不再依赖“自动箱体突破”告警开关决定图形是否显示。
- `显示历史箱体`：显示历史箱体，沿用当前历史箱体叠加结果。
- `显示通道`：显示当前识别到的通道。
- `自动箱体突破告警`：保持现有告警语义，只决定是否生成突破事件，不再兼作显示开关。
- `通道参数`：紧凑菜单，第一期提供通道锚点间距、最少 K 线、最大违规；当前与历史箱体继续沿用已有稳定识别规则，箱体参数留待后续研究迭代。

顶栏、交易工具菜单和中央工作区均不新增自动通道入口。默认所有显示及告警均为关闭。

## 数据与渲染

K 线数据加载完成后，自动箱体和通道叠加结果随 `KlineChartPayload` 一起生成。箱体继续使用现有 `BoxDetectionConfig` 与当前有效性规则；通道复用旧自动通道模块的 `ChannelDetectionConfig` 和识别实现。两类叠加都转换为 K 线图表已使用的索引坐标与价格坐标；网页图表和原生图表均能安全忽略未启用的层。

模块参数与开关保存到既有 K 线工作区记录，按 `API + 标的 + 周期` 分开保存。加载旧记录时，缺失字段一律采用关闭和默认检测参数，保证兼容。

## 边界

- 不删除 `roll_terminal_qt/auto_channel_window.py` 或 `okx_quant/auto_channel_*`；它们仍是研究与后续扩展的参考实现。
- 不恢复自动通道或划线交易台的独立菜单入口。
- 不修改 RR、画线条件单、专业套利、订单提交或已有 API 绑定规则。
- 通道识别失败、数据不足或参数无效时，只清空该图层并显示简短状态，不影响 K 线本身加载。

## 验收

1. 新启动 K 线页的自动箱体、历史箱体、通道和突破告警均关闭。
2. 开启自动箱体只显示当前箱体，不自动启用突破告警。
3. 开启通道时，K 线载荷含通道叠加；关闭时不发送通道层。
4. 关闭/打开模块或重新加载同一工作区后，参数和开关保持一致。
5. 原有箱体突破告警、RR 与条件单相关测试继续通过。

# OKXQQ 策略运行状态定时邮件设计

## 目标

在 OKXQQ 主程序运行期间，每天按电脑的 Asia/Shanghai 本地时间在 `08:00`、`12:00`、`16:00`、`20:00` 自动发送一封策略运行状态邮件。每封邮件统一汇总所有 API 下的活跃策略会话，排除已停止会话，并沿用软件现有的全局 SMTP、全局发件邮箱和全局收件人配置。

本次只增加状态汇总与定时发信能力，不增加新的邮箱配置界面，不改变策略执行、下单、风控或现有交易通知行为。

## 已确认需求

- 目标程序是 OKXQQ 主程序。
- 每天固定发送四次：`08:00`、`12:00`、`16:00`、`20:00`。
- 只有 OKXQQ 主程序正在运行时才需要触发。
- 一封邮件覆盖全部 API，不按 API 拆成多封。
- 只列活跃会话；已停止的历史会话不进入邮件。
- 使用现有全局 SMTP、全局发件邮箱和全局收件人。
- 邮件发送不得阻塞策略线程或主界面。
- 每个日期和时段最多触发一次，重启后也不能重复触发同一时段。

## 方案选择

### 采用：OKXQQ 主界面内置轻量调度

主界面在 UI 线程中周期性进行很轻量的时间检查。到达待发送时段时，先在 UI 线程中取得不可变的会话快照，再把邮件发送交给现有异步 SMTP 能力。

选择该方案的原因：

- `self.sessions` 就是当前策略会话的权威内存数据源，邮件可与界面保持同一口径。
- 项目已有 `EmailNotifier` 和主界面定时回调机制，可以最小范围复用。
- 不需要新进程、进程间通信或 Windows 任务计划。
- UI 线程只做时间判断和快照生成，网络发送继续在后台执行。

### 未采用：独立后台调度线程

独立线程需要跨线程读取 UI 管理的会话数据，并额外处理关闭、并发和竞态，收益不足。

### 未采用：Windows 任务计划

外部任务无法可靠取得 OKXQQ 内存中的实时浮盈和运行状态，也不符合“只在主程序运行时发送”的约束。

## 组件设计

### 1. 状态邮件纯逻辑模块

新增一个聚焦于策略状态邮件的模块，职责限定为：

- 定义四个固定发送时段。
- 判断一次定时检查是否跨过了某个应发送时段。
- 从调用方传入的会话快照生成主题、纯文本正文和 HTML 正文。
- 读取和保存已触发的“日期+时段”键。

该模块不直接访问 Tk 控件、不请求 OKX 接口，也不操作策略引擎，便于单元测试。

### 2. OKXQQ 主界面集成

主程序启动后注册周期检查，并维护本次进程的 `last_check_at`：

- 首次检查只建立时间基线，不追补程序启动前错过的邮件。
- 后续检查若跨过一个发送时段，则触发该时段。
- 若电脑休眠后恢复并跨过多个时段，只触发最近一个时段，避免一次补发多封过期邮件。
- 触发前检查持久化记录；已存在相同“日期+时段”键则跳过。
- 主窗口销毁后不再安排下一次检查。

周期检查建议为 30 秒一次。该频率仅用于发现时段，不进行网络读取，对策略运行影响可忽略。

### 3. 会话快照

快照覆盖 `self.sessions` 中全部 API 的活跃会话。活跃口径复用现有运行汇总语义，包括策略引擎仍在运行，或会话处于运行中、停止中、待恢复、恢复中等仍需关注的状态；明确排除已停止会话。

快照只读取界面当前已有的数据与缓存，不为了邮件临时调用 OKX API。这样可以避免定时邮件给交易接口增加负载，也确保邮件展示的是用户当时在主界面能看到的口径。

每行包含：

- 会话
- API
- 账户总权益
- 策略
- 标的
- 方向
- 开仓数量
- 开仓价
- 止损价
- 止盈价
- 实时浮盈亏
- 净盈亏
- 上次净盈亏
- 状态
- 启动时间
- 风险金

缺失或尚未刷新的数据统一显示 `-`，不能因为单个字段缺失而放弃整封邮件。明细按 API 名称、会话号稳定排序。

## 邮件格式

主题格式：

```text
[OKXQQ] 策略运行状态 | 2026-07-18 08:00 | 活跃 10
```

正文先给出：

- 计划时段和实际生成时间
- 活跃会话总数
- 涉及的 API 数量
- 各 API 的活跃会话数量

随后给出会话明细。纯文本正文用于所有邮件客户端的兜底展示；HTML 正文使用简单表格，所有动态文本必须进行 HTML 转义。

当没有活跃会话时仍发送邮件，主题中的活跃数量为 `0`，正文明确写“当前无活跃策略”。这封空状态邮件用于确认 OKXQQ 与邮件链路仍然正常。

## 发件配置

状态汇总邮件始终使用全局发件邮箱和全局收件人，不使用某个当前选中 API 的专属发件邮箱覆盖。原因是一封邮件同时覆盖多个 API，不应由任意一个 API profile 决定发件身份。

SMTP 服务器、端口、SSL、用户名和密码继续复用现有通知配置，不新增或复制敏感配置。

## 去重与持久化

每次触发使用类似 `2026-07-18T08:00` 的键。触发流程为：

1. 确认该键未记录。
2. 将该键写入 OKXQQ 用户数据目录下的轻量状态文件。
3. 生成会话快照并提交异步发送。

先落去重记录再发信，可以防止 SMTP 线程尚未结束时 UI 重复触发，以及程序在发送过程中重启造成重复邮件。发送失败不会在同一时段反复重试，以免认证错误或网络故障形成邮件风暴；下一计划时段会再次正常尝试。

状态文件只保留近期键，例如最近 14 天，避免无限增长。文件损坏或不可读时记录日志并安全回退为空记录，不能影响主程序启动或策略运行。

## 错误处理与日志

- 未启用邮件通知、SMTP 配置不完整或无收件人：记录一次清晰的跳过日志。
- 快照中单个会话字段异常：该字段显示 `-`，其他会话继续生成。
- 邮件生成异常：记录失败原因，不影响下一次调度。
- SMTP 认证、连接或发送失败：沿用现有 `EmailNotifier` 日志，不弹出阻塞式对话框。
- 状态文件读取或写入失败：记录错误；本次调度安全退出，不影响交易线程。
- 所有新增日志都不得输出 SMTP 密码、授权码或完整敏感凭据。

## 测试设计

新增纯逻辑单元测试，至少覆盖：

1. 四个固定时段的识别。
2. 普通周期检查跨过单个时段时触发。
3. 休眠跨过多个时段时只选择最近一个。
4. 首次启动检查不追补程序启动前时段。
5. 相同“日期+时段”在内存和重启后的持久化去重。
6. 活跃会话被保留、已停止会话被排除。
7. 多个 API 汇总进同一封邮件并稳定排序。
8. 主题、摘要和全部明细字段正确。
9. HTML 特殊字符被转义。
10. 无活跃会话时仍生成有效邮件。
11. 缺失字段显示 `-`。
12. SMTP 未配置、发送异常及状态文件异常不会影响调度循环。

集成回归验证应确认：

- OKXQQ 启动后调度回调已注册。
- 邮件发送仍通过后台线程执行。
- 现有策略启动、停止、持仓刷新和交易邮件测试保持通过。

## 验收标准

- OKXQQ 连续运行时，每天四个计划时段各触发一次状态邮件。
- 单封邮件包含全部 API 的活跃策略，不包含已停止会话。
- 邮件字段与主界面策略会话表的展示口径一致。
- 没有活跃策略时仍收到明确的空状态邮件。
- 电脑休眠跨时段后只补最近一封；首次启动不补发启动前邮件。
- 同一日期和时段在程序重启后不会重复触发。
- 邮件失败、配置缺失或状态文件损坏均不阻塞 OKXQQ 和策略运行。
- 不新增邮箱密码配置，不改变现有策略和交易逻辑。

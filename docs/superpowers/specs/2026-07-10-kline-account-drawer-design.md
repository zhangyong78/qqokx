# K 线分析账户抽屉设计

## 目标

在“K线分析”窗口右侧图表区域下方增加一个可展开、收起并可调整高度的账户抽屉。用户查看 K 线时，可以同时查看当前账户的委托和持仓；委托允许撤单，持仓仅供查看。

本次改动只覆盖账户抽屉及其必要的数据读取、筛选和撤单流程，不增加平仓、下单、历史委托或持仓编辑功能。

## 页面结构

现有页面保持“左侧控制栏 + 右侧图表区”结构。右侧图表区内部改为垂直分割布局：

- 上方是现有 K 线图及双图联动内容。
- 下方是账户抽屉。
- 分隔线允许用户拖动，从而动态调整 K 线与账户抽屉的高度比例。
- 账户抽屉默认收起，避免影响现有 K 线可视面积。
- 页面提供“委托 / 持仓”入口按钮。点击后展开抽屉并切换到对应标签；再次触发当前入口或点击抽屉内的收起按钮时关闭抽屉。

账户抽屉包含：

- “当前委托”标签。
- “当前持仓”标签。
- “当前交易对 / 全部”范围筛选，默认选择“当前交易对”。
- 手动刷新按钮。
- 数据状态文字，包括加载中、更新时间、空数据和错误信息。

## 数据范围与联动

抽屉使用 K 线页面当前选中的 API 账户及环境，不增加独立账户选择器。

“当前交易对”筛选使用 K 线页交易对输入框的规范化大写值；“全部”显示当前账户中全部符合条件的数据。

以下事件会触发已展开抽屉的数据刷新：

- 首次展开抽屉。
- API 账户成功切换。
- K 线交易对确认变更。
- 用户点击手动刷新。
- 撤单成功。

切换“当前交易对 / 全部”只对最近一次完整账户快照做本地筛选；若尚无快照，则先读取数据。抽屉收起时不启动周期性刷新，避免增加无用请求。本次不增加自动轮询。

## 数据读取

新增轻量账户快照加载线程，复用项目现有运行时账户信息与 OKX 客户端能力，读取：

- 当前有效持仓。
- 当前普通委托。
- 当前算法委托。

网络读取不得在 GUI 主线程执行。加载期间保留上一次成功结果，并在状态文字中显示“正在刷新”；读取失败时继续显示已有数据，同时显示错误信息。若当前账户不可用或尚未解锁，则不发起读取，并提示用户先选择或解锁账户。

为避免账户快速切换或连续刷新导致旧结果覆盖新结果，每次读取携带请求代次；界面只接收当前账户、环境和请求代次相匹配的结果。

窗口关闭时停止账户加载及撤单工作线程，不阻塞现有 K 线加载线程的清理流程。

## 当前委托

委托表显示普通委托和算法委托，并保留数据对象与表格行的稳定映射。最小展示列为：

- 合约
- 来源（普通 / 算法）
- 方向
- 委托类型
- 委托价或触发价
- 委托量
- 已成交量
- 状态
- 更新时间
- 委托标识

没有符合当前筛选的数据时显示空表和“当前没有委托”状态，不插入伪数据行。

“撤单”按钮仅在选中有效委托时可用。撤单流程为：

1. 根据委托来源确定普通撤单或算法撤单接口。
2. 弹出二次确认，显示合约、方向、类型和委托标识。
3. 用户确认后在后台线程提交撤单，并暂时禁用撤单按钮，防止重复提交。
4. 撤单成功后显示结果并刷新完整账户快照。
5. 用户取消确认时不改变数据；撤单失败时保留当前表格和选中行，并显示错误。

## 当前持仓

持仓表只读，最小展示列为：

- 合约
- 方向
- 持仓量
- 可平量
- 开仓均价
- 标记价格
- 未实现盈亏
- 保证金模式
- 持仓模式

本次不提供平仓、修改保证金、止盈止损或其他持仓操作。没有符合当前筛选的数据时显示空表和“当前没有持仓”状态。

## 组件边界

账户抽屉作为 K 线窗口内的轻量、独立组件构建，负责：

- 抽屉 UI、标签、筛选和表格。
- 账户快照加载状态。
- 当前委托选择和撤单交互。

K 线窗口负责向抽屉提供当前运行时、账户名称、环境和交易对，并在账户或交易对变化时通知抽屉。抽屉不读取或修改 K 线工作区、画线、RR、图表渲染和告警状态。

不直接嵌入完整账户主页，也不为本次功能重构账户主页。可以复用现有账户线程、委托模型和格式化辅助函数，但应避免复制完整页面逻辑。

## 错误与安全处理

- 未选择账户、账户无效或账户未解锁：显示提示，不请求私有接口。
- 数据读取失败：保留最后一次成功数据并显示错误，不影响 K 线加载和操作。
- 未选择委托：撤单按钮禁用。
- 委托缺少可用撤单标识：不调用接口并显示说明。
- 撤单必须经过用户确认。
- 撤单进行中禁止再次提交撤单。
- 过期线程结果不得覆盖新账户或新请求的数据。

## 测试与验收

自动测试至少覆盖：

- 页面存在“委托 / 持仓”入口，抽屉默认收起。
- 点击入口可展开抽屉、切换标签并收起；分割布局不会移除原 K 线组件。
- 默认筛选为“当前交易对”，切换“全部”后正确显示完整快照。
- 交易对确认变更和 API 账户切换会刷新已展开抽屉。
- 当前交易对筛选对委托与持仓都生效。
- 普通委托与算法委托展示正确，并走各自撤单接口。
- 未选择委托、取消确认和重复提交不会调用撤单接口。
- 撤单成功刷新数据，撤单失败保留原表格。
- 旧请求结果不会覆盖较新的账户快照。
- 数据加载失败不会影响 K 线图继续使用。

人工验收步骤：

1. 打开“K线分析”，确认初始 K 线区域与现有行为保持一致。
2. 点击“委托”，确认下方抽屉展开，K 线自动缩小且分隔线可拖动。
3. 在“当前交易对”和“全部”之间切换，核对委托和持仓列表。
4. 切换 K 线交易对及 API 账户，确认抽屉随当前上下文刷新。
5. 对普通委托和算法委托分别验证撤单确认、成功和失败反馈。
6. 确认持仓区域没有平仓入口。

## 兼容与修改范围

实施只修改 K 线分析窗口、必要的轻量辅助代码及对应测试。当前工作区已有未提交改动必须完整保留，不做无关重构，不改变账户主页、K 线工作区持久化格式或现有交易执行行为。

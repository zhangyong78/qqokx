# 定时行情邮件数据新鲜度设计

## 目标

定时行情邮件继续允许在上游数据过期时发送，但必须让读者一眼看到每个分析块和每张图的实际数据时间、数据源、收盘状态及过期警告，同时避免错过任务集中补跑造成的并发、重复发送和静默降级。

## 已确认问题

- 2026-07-24 09:21，00:00、04:00、08:00 和前一日 20:00 四个任务因 `StartWhenAvailable` 同时补跑。
- 并发请求失败后，行情分析静默回退到截至 2026-07-23 12:00（UTC+8）的缓存；邮件仍显示 2026-07-24 的生成时间。
- 图表加载在缓存数量足够时完全跳过实时请求。
- BTC 波动率在分析和制图阶段重复抓取；失败时无提示地降级为程序历史波动率，图和文字可能不是同一批数据。
- 最近复盘只在报告不存在时生成，现有报告从 2026-06-17 起未刷新。
- 同一分析批次的重复投递会被复盘当作多个独立样本。
- 图表抓取或渲染失败时只显示空图，不说明数据源、数据时间或失败原因。

## 数据快照

一次邮件分析中，每个标的和周期只保留一份行情快照。分析文字、指标数值、K 线形态和图表优先共用这份快照。BTC EMA15/MA50 与 BTC 波动率补充分析保存用于绘图的短窗口数据，邮件准备阶段不得再次抓取波动率。

行情请求失败时可以使用本地缓存，但快照必须记录实际最后一根 K 线时间和来源。波动率优先使用 Deribit 波动率指数；失败后可降级为程序历史波动率，但必须明确显示“降级”。

## 时间与警告

所有时间显示为北京时间 `UTC+8`。每张 `1H / 4H / 1D / 1W` 图显示：

- 数据更新至时间；
- `已收盘` 或 `进行中`；
- 数据源；
- 正常或过期状态。

过期阈值：

- `1H`：2 小时；
- `4H`：6 小时；
- `1D`：36 小时；
- `1W`：8 天。

超过阈值仍发送邮件，但邮件顶部显示红色总警告，对应图表显示红色“数据已过期（滞后 X）”。无图时显示原因，不再只有空白占位。

简明结论和明确观点显示其行情快照时间；最近复盘显示报告生成时间和样本截止时间；BTC 两个补充分析的每个周期行也显示数据时间。

## 复盘

最近复盘报告超过 24 小时即在下一封邮件准备时自动刷新。重复投递但 `report_path + symbol` 相同的记录只计一个样本；缺少报告路径时使用 `generated_at + symbol` 去重。刷新失败时保留旧结果并显示过期警告，邮件继续发送。

## Windows 调度

只有 `08:00` 任务保留“错过后补跑”，用于电脑恢复可用后补发当天邮件。`00:00 / 04:00 / 12:00 / 16:00 / 20:00` 不补跑，避免旧时段集中启动。现有每个任务的 `MultipleInstances IgnoreNew` 保持不变。

## 验证

- 单元测试覆盖时间格式、过期判定、降级标签、图表时间渲染、复盘过期刷新和重复样本去重。
- 相关邮件、分析器和任务管理测试全部通过。
- 生成一份不发送的真实预览归档，核对数据时间、波动率来源、过期警告和空图提示。
- 重新注册 Windows 任务后，确认仅 `08:00` 的 `StartWhenAvailable=True`。

## 范围

只修改多币行情邮件、复盘加载、邮件调度注册脚本及对应测试，不改变交易策略、指标参数和其他界面。

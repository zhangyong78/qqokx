# BTC日线+4小时多空策略 实现计划

## 需求复述

新增一个独立策略，名称为 `BTC日线+4小时多空策略`，不修改原有 BTC 回踩做多/做空策略。

本次只做回测策略与对应 UI 参数接入，便于你直接回测。图二里的 K 线分析交易机会提示不在这一步实现。

## 规则范围

1. 标的固定为 `BTC-USDT-SWAP`
2. 入场周期固定为 `4H`
3. 日线方向过滤固定为：
   - 日线收盘价 > 日线 `MA50`，只允许 4H 做多
   - 日线收盘价 < 日线 `MA50`，只允许 4H 做空
4. 4H 入场逻辑：
   - 先出现 `EMA15` 与 `MA50` 的方向穿越
   - 穿越后等待回踩/反抽 `EMA15`
   - 回踩确认后，下一根 4H 开盘入场
5. 默认回踩次数先用研究结论里的统一版本：`max_pullback_index = 1`
6. 出场逻辑：
   - 若 4H 收盘重新站回/跌回 `EMA15` 反方向，则下一根 4H 开盘平仓
   - 否则使用动态止盈：
     - `2R` 提到开仓价加双向手续费
     - `3R` 锁 `1R`
     - 之后每多走 `1R`，止损再推进 `1R`

## 实现方案

1. 新增单独策略 ID 与目录定义，名称显示为 `BTC日线+4小时多空策略`
2. 新增一个 BTC 双向回踩策略模块，复用现有多头/空头候选信号扫描规则
3. 在回测引擎里新增该策略分支，统一处理多头和空头交易
4. 在参数配置和 UI schema 里固定：
   - `bar = 4H`
   - `ema_type = ema`
   - `ema_period = 15`
   - `trend_ema_type = ma`
   - `trend_ema_period = 50`
   - `daily_filter_enabled = true`
   - `daily_filter_bar = 1D`
   - `daily_filter_boundary = exchange`
   - `daily_filter_mode = close_vs_ma`
   - `daily_filter_ma_type = ma`
   - `daily_filter_period = 50`
5. UI 交互沿用现有“动态委托做多”一类动态止盈参数编辑方式，只暴露这次回测需要调的参数

## 风险与控制

1. 现有长/短回踩策略是分开的，新双向策略需要合并同一时间轴上的候选信号，必须避免同一根 K 线重复开仓
2. 日线过滤需要固定为 `close_vs_ma/MA50`，不能被旧默认值覆盖
3. 批量回测参数矩阵如果误走旧分支，会生成不需要的组合；新策略先保持单配置直跑

## 验证

1. 参数与 UI 默认值测试
2. 策略目录 / runtime 注册测试
3. 新双向回测最小样例测试，验证：
   - 日线多头时只开多
   - 日线空头时只开空
   - `signal_mode` 仍可限制只做多或只做空

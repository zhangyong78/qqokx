# 2026 年 7 月最佳参数组合包 vs ReapAI 实盘对比报告

生成时间：2026-08-02（Asia/Shanghai）

## 结论摘要

- **方向相符。** 两边 7 月均为亏损：使用 ReapAI 实际费率重跑的回测净损益为 **-361.53 U**，ReapAI 实盘已实现净损益为 **-374.61 U**，实盘比回测少 **13.08 U**（约为回测绝对损失的 3.62%）。
- **价格/策略层面基本相符。** 回测交易毛损益为 **-318.58 U**，实盘交易毛损益为 **-323.13 U**，仅差 **-4.55 U**。这说明 7 月的大方向和主要价格结果没有出现“回测赚钱、实盘大亏”的失真。
- **成本口径存在明确问题。** 当前组合包正式回测代码的多头费率为 Maker 0.010% / Taker 0.028%，ReapAI 实际成交费率为 Maker 0.015% / Taker 0.036%。实盘手续费为 **-48.71 U**，校准后回测手续费为 **-42.95 U**，仍少计 **5.76 U**；回测还未计入实盘资金费 **-2.77 U**。
- **逐笔可追溯性不足。** ReapAI 的 7 月策略会话快照未写入本地 `strategy_history.json`，不能把每一笔实盘交易严格关联到当时的参数快照、信号 K 线和退出原因。订单客户端标识可高可信地识别为动态多头（`emaent` / `emaslg`）与斜率空头（`stgent`），但这不能替代正式策略账本。

结论：**本月结果“基本相符，但成本模型和审计链路不完整”。** 可认可策略方向与价格层面的回测有效性；在修正费率、纳入资金费并补齐实盘策略账本前，不应把当前净收益回测当作精确实盘净收益预测。

## 范围与口径

- 策略：最佳参数组合包中的 8 条 1H 策略，BTC / ETH / SOL / DOGE 各一条动态多头和一条均线斜率空头。
- 风险金：按参数包实盘映射重跑，而非统一 100U：多头 BTC/ETH/SOL/DOGE = 20/12/4/4U；空头 BTC/ETH/SOL/DOGE = 10/8/6/6U。
- 回测数据：本地确认收盘的 1H K 线；四个币种均覆盖完整 2026-07，最新确认数据到 2026-08-01 11:00（北京时间）。按**平仓时间**归属 2026 年 7 月。
- 回测成本：滑点保持原最佳参数组合包设定；多头使用 ReapAI 实际 Maker 0.015% / Taker 0.036%，空头双边 Taker 0.036%。
- 实盘数据：`ReapAI/live/position_history.json` 中 2026-07-01 至 2026-08-01（北京时间）平仓的记录；仅保留 `isLatestSnapshot=true`。得到 111 条唯一 lifecycle 记录，无重复快照。

## 差异归因

实盘与校准回测的净差 -13.08U 可以完整分解为：

| 差异来源 | 对实盘相对回测的影响 |
| --- | ---: |
| 交易毛损益（包含实际成交价、信号/退出差异） | -4.55 U |
| 手续费 | -5.76 U |
| 资金费 | -2.77 U |
| 合计净差 | **-13.08 U** |

这表示差异并非主要来自行情预测失效。成本与交易序列差异合计占大头，且资金费是原回测完全遗漏的实盘成本。

## 发现的问题及优先级

### P1：多头费率模型落后于 ReapAI 实际费率

回测目前对多头使用 Maker 0.010% / Taker 0.028%；ReapAI 资料及 7 月成交实际为 Maker 0.015% / Taker 0.036%。空头回测双边 Taker 0.036% 与实盘费率一致。

影响：旧费率口径下 7 月回测为 -358.28U；按实际费率重跑后为 -361.53U。动态保护中的“手续费偏移”还会改变出场与后续交易序列，因此不能只在旧结果上做静态扣费。

建议：将组合包正式回测费率从硬编码常量改为读取所选实盘 profile 的费率，并在报告 manifest 中固定写入费率来源、数值和 profile 名称。

### P1：回测未计入资金费

ReapAI 7 月资金费合计 -2.77U。金额不大，但它解释了净差的一部分；在持仓时间更长或资金费极端时会放大。

建议：回测按交易持仓区间、资金费结算时点与历史费率计入；至少提供“0 / 历史实际 / 压力情景”三种资金费口径。

### P2：ReapAI 缺少策略会话与逐笔账本映射

7 月 ReapAI 没有对应的 `strategy_history` 记录。本报告依靠订单客户端 ID 模式和仓位历史识别策略类别，无法逐笔验证：当时运行的参数版本、信号时间、挂单取消原因、保护单触发原因及是否人工干预。

建议：每次策略启动将 profile、参数快照、session ID 写入历史；每笔开平仓记录 order ID、fill ID、信号 K 线、预期价、实际价、止盈止损原因和资金费。这样后续能做 1:1 交易配对，而不是只做月度聚合。

### P2：策略交易数存在小幅偏差，需要版本锁定后逐笔定位

校准回测 109 笔、实盘 111 笔。偏差集中在 BTC 动态多头（+1）、ETH 动态多头（+1）、ETH 斜率空头（-2）、SOL 动态多头（+2）、DOGE 斜率空头（-1）。这些偏差会改变个别策略收益，尤其是 BTC 动态多头。

建议：补齐上项账本后，按“信号 K 线 + 币种 + 方向 + 进场时间容差”匹配交易；将未匹配项分类为信号差异、挂单未成交/取消、保护规则差异、手续费偏移差异、人工操作或数据缺口。

## 可操作判断

- 若问题是“策略在 7 月是否跑偏”：**没有跑偏的证据**。整体毛损益和亏损方向高度接近。
- 若问题是“回测能否直接代表实盘净损益”：**目前不能精确代表**。费用与资金费使净值预测偏乐观，且缺少逐笔审计链路。
- 若问题是“是否需要立刻停用”：仅凭本月对比不足以支持该结论；但在下一轮实盘前，应先完成费率同步、资金费计入和 ReapAI 账本落库，再继续用逐笔偏差监控策略一致性。
